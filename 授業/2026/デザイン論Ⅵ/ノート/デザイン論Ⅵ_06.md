# 第6回

- なぜフレームワークがいるのか？
	- 考え方 / 観点の「型」の習得
	- チーム内の誤解やボタンのかけ違いを防ぐ
	- チーム外との共有 / 発信に説得力を持たせる
- バウンダリーオブジェクト
	- 共通で確認しあえて、初めて見る人でもわかるもの。
	- 三人寄れば文殊の知恵…というよりも、静かな喧嘩になりがち。
- プロセスの全体像
	- 共感
		- ペルソナ
			- 理想像や願いを書く。
			- あくまでテーマに沿った内容。
			- 絶対にこの人を幸せにするという、愛したいユーザーを決めることが重要。
				- チームメンバーみんなが推せることが重要！
		- 共感マップ
			- 何を考えてる？
			- 何を感じてる？
			- 何を見てる？
			- どんなことを言う？
			- 何をする？
			- 何を聞く？
	- 定義
		- As is / to Be
		- 常に変化することを念頭に置く。
	- 創造
		- カスタマージャーニーマップ
			- ユーザーが触れるUI（接点）について洗い出す。
			- ==ストーリーの中での感情の起伏をイメージして書く。==
		- ステークホルダーマップ
			- 物語を構成するすべての登場人物の相関図。
	- プロトタイピング
		- プロトタイピング
	- テスト
		- ストーリーボード（絵コンテ）
			- カスタマージャーニーを書く前のあたりをつけるときにも使う。
			- わかりやすく体験価値をヴィジュアライズして伝えるための資料として扱う。
